# JARVIS AI Assistant

JARVIS is a Python-based AI assistant for technical work, authorized cybersecurity learning, and everyday desktop automation. It combines Groq-powered conversation with text, voice, and browser interfaces, while keeping local actions behind explicit allowlists, environment switches, confirmations, workspace boundaries, and audit logging.

Use JARVIS to ask technical questions, speak with a voice-enabled assistant, open or close approved applications, create workspace files, control selected system actions, and perform limited passive reviews of public URLs. It is designed for transparent, permission-based assistance rather than unrestricted command execution.

**GitHub description:** A safety-focused Python AI assistant with Groq chat, text and voice modes, a JARVIS-style web UI, guarded desktop automation, workspace file writing, and passive URL assessment.

## Requirements

- Python 3.10 or newer
- A Groq API key
- Optional voice packages:

```powershell
pip install groq numpy sounddevice pyttsx3 SpeechRecognition
```

Set the API key in PowerShell:

```powershell
$env:GROQ_API_KEY="your_key_here"
```

Do not put API keys in this README, source files, audit logs, or chat messages.

## Start JARVIS

Text mode:

```powershell
python .\foog.py --mode text
```

Voice mode:

```powershell
python .\foog.py --mode voice
```

Web mode:

```powershell
python .\javi.py --web
```

Open `http://127.0.0.1:5000` in a browser. Web mode supports typed chat, browser voice input/output, and guarded `/open` and `/close` application commands. Include an explicit trailing `yes`, for example `/open notepad yes` or `/close notepad yes`. Other local actions remain CLI-only.

Say `Jarvis stop`, `stop speech`, or `stop talking` while JARVIS is speaking to interrupt voice output.

## Permissions

Normal chat does not execute commands. Side-effecting actions are disabled by default.

Enable local actions explicitly for the current PowerShell session:

```powershell
$env:JARVIS_ENABLE_COMMANDS="1"
```

Enable passive URL scans separately:

```powershell
$env:JARVIS_ENABLE_SCANS="1"
```

Restart JARVIS after changing these settings. `/open`, `/write`, and `/system` run directly after their allowlist and workspace checks. `/run` and `/scan` still require typing the exact confirmation `YES`.

## Commands

### Open an application

```text
/open notepad
/open editor
/open terminal
/open browser https://example.com
```

Voice examples:

```text
Jarvis, open notepad
Jarvis, open editor
Jarvis, open browser https://example.com
```

Only applications in the built-in allowlist can be opened.

### Close an application

```text
/close notepad
/close editor
/close terminal
```

Closing is limited to the built-in process allowlist and is currently supported on Windows.

### Write a note or code file

```text
/write notes.txt | Meeting notes
/write data.csv | name,score
/write src/example.py | print("Hello")
```

Voice examples:

```text
Jarvis, write note ideas.txt hello from Jarvis
Jarvis, write code example.py print hello
```

Files must use a supported text or code extension, including `.txt`, `.csv`, `.json`, `.yaml`, `.xml`, `.py`, `.js`, and `.html`, and stay inside the workspace. Existing files may be overwritten directly. Binary `.docx` and `.xlsx` files are not generated by this text writer.

Set a custom code editor if `code.cmd` is not on PATH:

```powershell
$env:JARVIS_CODE_EDITOR="C:\Path\To\Your\Editor.exe"
```

### System controls

```text
/system lock
/system sleep
/system shutdown
/system restart
```

Voice examples include `lock computer`, `sleep computer`, `shutdown computer`, and `restart computer`. These actions run directly and may affect the whole computer.

### Authorized reconnaissance command

```text
/run nmap -sV 192.0.2.10
/run curl -I https://example.com
```

Only the built-in reconnaissance executable allowlist is accepted. Shell pipelines, redirection, chaining, and substitutions are rejected. Use only against systems you own or are explicitly authorized to test.

### Passive URL assessment

```text
/scan https://example.com
/scan https://example.com report.json
```

Voice example:

```text
Jarvis, scan https://example.com report.json
```

The scan requires `JARVIS_ENABLE_SCANS=1`, exact `YES` confirmation, and a public HTTP or HTTPS URL. It performs limited passive checks for headers, HTTPS, cookies, CORS, forms, and technology disclosure. It does not crawl, brute-force, exploit, authenticate, follow redirects, or modify the target.

The report is written as one JSON file inside the workspace. It includes observations, limitations, bug-bounty methodology, recommended tools, and suggested commands. Suggested commands are not executed automatically and require separate authorization.

## Audit log

JARVIS writes minimal JSONL action events to `jarvis_audit.jsonl` by default. Change the location with:

```powershell
$env:JARVIS_AUDIT_LOG="C:\Path\To\jarvis_audit.jsonl"
```

Audit records should not contain API keys, passwords, tokens, or full prompts. Protect the log as sensitive local data.

## Safety boundaries

- Use only authorized targets and approved bug-bounty scope.
- Confirm ownership, allowed techniques, rate limits, and stop conditions before testing.
- Treat scan results as observations until manually validated.
- Do not use JARVIS for credential theft, malware, evasion, persistence, destructive activity, or unauthorized access.
- Never share system prompts, credentials, API keys, or private data with the assistant.
